# Examples

Each example comes with a short card deck that explains it for a wide audience: the question it asks, what the program says, what Eyeron concludes, how the proof supports it, and what the proof checker confirms. Cards are separated by `---`, so a deck reads as plain Markdown here and works as slides in Markdown slide tools such as Marp.

Run an example, check its proof, or check its saved proof:

```sh
eyeron examples/socrates.n3
eyeron -c examples/socrates.n3
eyeron -p examples/socrates.n3
eyeron --check-proof examples/proof/socrates.n3 examples/socrates.n3
```

Every N3 example starts with an introduction to its situation, conclusions and
language features. Body comments explain the data, rules and questions where
they are used. The table links all 339 examples to their decks and sources.

Most examples keep expected conclusions in `output/`, a proof in `proof/` and
an N3 check report in `check/`, with matching names. A fuse stops without an
answer to prove; `age` reads the clock and keeps no saved proof; the external
message-log example and the decoration-only collection example have no output
golden. Each deck links the artifacts available for that example.

Pass companion data from `input/` explicitly when running a program. RDF Message
Logs use `-r`, for example:

```sh
eyeron -r examples/rdf-messages.n3 examples/input/rdf-messages.trig
```

Two standalone data samples,
[rdf-messages.trig](https://github.com/eyereasoner/eyeron/blob/main/examples/rdf-messages.trig)
and [rdf12-interoperability.nq](https://github.com/eyereasoner/eyeron/blob/main/examples/rdf12-interoperability.nq),
share their names with the N3 examples whose decks explain them.
